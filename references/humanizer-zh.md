# 日报去模板化参考

本参考把 Humanizer-zh 的原则收窄到中文工作日报。它服务于最后一次编辑，不替代 Git 证据或用户确认。

## 先保事实

- 保留 commit 短哈希、日期、数字、文件名、命令、错误信息、状态词和用户的技术判断。
- 不为了“像人”而添加不存在的感受、结果、用户反馈、业务价值或因果关系。
- “已推送”只在远程或上游引用有证据时使用；否则写“上游引用已可见”或“无法核实”。

## 优先改掉的表达

- 空泛意义：作为……的证明、标志着、体现了重要性、为……奠定基础。
- 宣传口吻：无缝、强大、充满活力、开创性、令人印象深刻，除非是项目的正式名称或用户原话。
- 模糊归因：专家认为、行业报告显示、大家普遍认为；没有具体来源就删掉。
- AI 连接和填充：此外、值得注意的是、在这个时间点、为了实现这一目标、总体而言。
- 公式结构：不仅……而且/而是、从 A 到 B 的虚假范围、三项并列、空洞的“未来充满希望”。

## 改写手法

1. 用“做了什么、看到什么、还缺什么”替代抽象评价。
2. 优先使用简单的“是”“有”“改了”“失败”“卡在”等句式。
3. 混合短句和稍长的解释句；能用两项说清楚就不硬凑三项。
4. 减少破折号、粗体、表情符号和标题式的“标签：说明”列表。
5. 让句子有正常的工作语气，可以保留用户明确表达的第一人称，但不替用户制造态度。

## 交付前检查

- 每条完成点都能指向 commit 或用户回答。
- 每条未完成点都写明停留位置或剩余条件。
- 障碍和风险有现象、原因或影响，避免只写“存在风险”。
- 沉淀是具体做法、判断、决策或排查路径，不是“提升了能力”。
- 删除套话后，四个固定标题、事实和技术细节仍然完整。
